# Аким на 5 часов — Python + SQLite

Учебный симулятор инвестиций в Астану: 5 направлений, 14 инициатив, 5 районов, карта, диаграммы «факт / прогноз», сравнение команд и AI-редактор данных.

**Бюджет 10 млрд ₸. Одна единица кейса = 100 млн ₸.** Все показатели и стоимости синтетические. Границы районов загружаются из локальной копии опубликованного слоя геосервиса Астаны (23.09.2026). Сарайшык показан отдельно серым: его нет в учебном датасете.

## Запуск

Python 3.11+. Из каталога проекта:

```bash
python -m venv .venv
# Linux: source .venv/bin/activate
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python init_env.py
python run.py
```

Откройте http://127.0.0.1:8000 . Данные создаются в `data/akim.sqlite3` при первом запуске. Войдите под аккаунтом администратора или сотрудника. Служебные токены из `.env` предназначены для API-интеграций. `.env` не включён в GitHub или переносимый архив.

**Полная инструкция сервера: [DEPLOY_BREV.md](DEPLOY_BREV.md)**. Jupyter 8888, сайт 8080, Python за Nginx 8000. Подготовлены Docker Compose и отдельный Nginx.

## Возможности

- Каталог 14 мер с описаниями, ценами, районами, эффектами и задержками.
- Серверная проверка бюджета, повторов, конфликтов, пяти решений и ограничения 2 меры направления.
- Обновление карты, 10 показателей районов и диаграмм после выбора меры.
- Score с объяснением рисков, сильных сторон и синергий.
- Перебор допустимых сценариев с явной отметкой, завершён ли поиск полностью.
- SQLite: сценарии, сравнение, версии датасета, журнал изменений, история агента.
- Редактор районов, инициатив, полного датасета и текстов сайта; восстановление версий.
- OpenAI Responses API с инструментами чтения, расчёта и изменения рабочих данных.
- Городские события: снегопад, паводок, смог; резерв бюджета и перераспределение инициатив без изменения общего датасета.
- Конкретные рекомендации замены одной меры с расчётом прироста и кнопкой применения.
- Автоматическая презентация из 5 HTML-слайдов, автономный просмотр и печать в PDF.

## Численная модель

Горизонт — 8 кварталов. Эффект умножается на `(8 - lag) / 8`, затем учитываются синергии, показатели ограничиваются диапазоном 0–100.

```text
Score = 0.7 × средний взвешенный Score районов
      + 0.3 × Score слабейшего района
      − количество показателей ниже 40
```

Веса находятся в `seed/dataset.json`. Ровно 5 различных мер, не больше 2 в направлении. Подробные данные кейса допускают выбор из пяти направлений, не требуют ровно одной меры каждого вида. M1/M3 конфликтуют глобально; M4/M7 и M5/M13 — в одном районе.

Исходный Score **52.55768**. Полный перебор: **694395** допустимых сценариев, лучший **57.236735**, стоимость **9.8 млрд ₸**: M2 весь город, M3/M8/M9 Нура, M14 весь город. Поддержка слабейшего района и устранение критических показателей дают основной прирост. Это оптимум учебной модели, не рекомендация реального расходования бюджета.

## AI и доступ к базе

Заполните `OPENAI_API_KEY` в `.env`, перезапустите сервер. `OPENAI_MODEL` — разбор сценариев, `OPENAI_AGENT_MODEL` — агент с правом редактирования. По умолчанию оба `gpt-4.1-mini`. Без ключа формулы и интерфейс работают, нейросетевой ответ не имитируется.

Числа считает Python. AI вызывает `calculate_forecast` и объясняет результат. Использован [цикл инструментов Responses API](https://developers.openai.com/api/docs/guides/function-calling).

Агент редактирует весь рабочий датасет: показатели, цены, эффекты, бюджет, совместимость, сценарии и тексты сайта. Валидация сохраняет структуру кейса: 5 районов, 5 направлений, 10 метрик. Произвольный SQL, команды сервера и чтение секретов не предоставляются. Правки создают версии; сохранённый сценарий остаётся привязан к своим исходным данным. Проверка ожидаемой версии предотвращает перезапись параллельной правки.

API: `/docs`, `/openapi.json`. Защищённые запросы требуют `Authorization: Bearer <ADMIN_API_TOKEN или AGENT_API_TOKEN>`. Оба токена дают полные права на рабочие данные. Просмотр и численный расчёт открыты; OpenAI и изменения требуют входа. Внешний агент: `GET /api/agent/tools`, `POST /api/agent/execute`. Встроенный чат: `POST /api/agent/chat`.

## Проверка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Проверяются эталонный Score, тенге, ограничения, авторизация, версии, сохранность старых результатов, удаление сценариев с контролем версии, ограниченный поиск и Responses tool loop через имитацию HTTP. Реальные вызовы OpenAI и инструменты расчёта/редактирования проверены с настроенным локальным ключом. На другом сервере ключ нужно добавить заново. Docker/Nginx/Brev проверяются на Linux-сервере после установки. Карта использует Leaflet 1.9.4 (локальная копия с лицензией); подложка OpenStreetMap требует интернета.

## Структура

`app/model.py` — формулы; `app/optimizer.py` — перебор; `app/db.py` — SQLite и аудит; `app/agent.py` — OpenAI; `app/main.py` — FastAPI; `static/` — интерфейс; `seed/` — исходные данные; `deploy/` — Nginx; `backup_db.py` — согласованная резервная копия SQLite.

Перед показом: запустить сайт, настроить ключ, проверить запрос AI, добавить туннель 8080, открыть ссылку из приватного окна. Команды сравнивать на одной версии данных; не менять активный датасет во время соревнования.

Полная таблица соответствия, ограничения и сценарий защиты: [ACCEPTANCE.md](ACCEPTANCE.md). Проверка установленного сайта: `python verify_install.py --url http://127.0.0.1:8080`; добавить `--live-ai` для одного реального AI-анализа.

Карта: [источник границ](https://gis.esaulet.kz/server/rest/services/Hosted/raiony/FeatureServer/0). Цветные контуры, переключатель видимости, общий обзор и переход к району из легенды. При нажатии показаны факт, прогноз и критические показатели. Координаты меток размещены внутри соответствующих полигонов.


### Объяснение влияния решений

Блок «Почему изменился Score» раскрывает цепочку инициатива → показатели → район → Score. Для каждой меры сравнивается полный план с планом без этой меры при тех же условиях. Показаны задержка, синергии, ограничение 0–100, переход через порог 40 и три компонента изменения Score. Эти маржинальные эффекты нельзя складывать; общее изменение отдельно разложено на эффект события и эффект всего плана. Числа рассчитывает Python, а не языковая модель.


### Аккаунты, главная и сохранение

Главная страница доступна без входа и содержит только обзор: карту, текущий Score, бюджет, показатели и каталог. Обновление каждые 30 секунд при открытой вкладке; это получение актуальных данных БД, а не генерация случайных показателей.

При первом запуске создаётся администратор `admin` с паролем `admin` (или INITIAL_ADMIN_PASSWORD из окружения). Для пользователя user пароль 12345678. Пароль изменяется в «Главная → Настройки аккаунта». На публичном сервере смените начальный пароль. Администратор создаёт сотрудников в «Данные и агент → Аккаунты сотрудников», задавая логин, пароль и имя. Сотрудник работает со своим черновиком и сценариями, но не изменяет общие данные, аккаунты или настройки. Служебные ADMIN_API_TOKEN / AGENT_API_TOKEN продолжают работать для интеграций.

Миграция SQLite выполняется автоматически и сохраняет старые сценарии. Добавлены users, sessions, workspaces, login_attempts и владелец сценария. Старые сценарии доступны администратору. Пароли PBKDF2-SHA256 с индивидуальной солью; сессии на 7 дней в HttpOnly cookie, в БД хранится хеш токена. Выход и смена пароля отзывают сессии. Есть ограничение неудачных попыток входа и проверка источника cookie-запросов.

План, событие, версия данных, раздел, фильтр, выбранные районы, диаграмма, поля названия, черновики редактора, запрос агента и полученный AI-разбор сохраняются в персональном workspace. Автосохранение через 400 мс плюс локальная резервная копия при обновлении страницы. Конфликт двух вкладок не перезаписывает более новую серверную версию. Пароли и API-ключи в черновик не записываются. Текущий план привязан к версии; обновления общей БД отражаются на главной без незаметной подмены условий плана.

«Найти лучший сценарий» выполняет поиск и затем автоматически запускает подробный AI-разбор (при рабочем OPENAI_API_KEY): причины выбора мер, положительные и отрицательные последствия, риски, нерешённые проблемы, этапы внедрения и улучшения. Недоступность API отображается явно. Готовый ответ сохраняется, после перезагрузки повторно модель не вызывается. Кнопки инструментов на главной объединяют поиск, AI-экспертизу, рекомендации, презентацию, сохранение и стресс-тест.


### Инструменты на главной и «Мои результаты»

У вошедшего пользователя инструменты находятся непосредственно на главной, отдельная вкладка убрана. Ниже — визуальная библиотека с фильтрами: черновик, сценарии, результаты поиска, AI-разборы, рекомендации, презентации. Карточки содержат Score, изменение, бюджет и дату. Открытие карточки не меняет текущий план: для этого есть отдельная кнопка в просмотре. Презентации открываются во встроенном окне и доступны для скачивания. Гостям эти персональные блоки не показываются.

Результаты инструментов сохраняются в таблице user_results с владельцем и снимком прогноза. Совпадающий тип/план/название/версия/событие обновляет существующую карточку без дубликатов. Ранее сохранённые сценарии и текущий черновик тоже отображаются; прежний AI-ответ доступен внутри черновика. Старые скачанные презентации, не сохранявшиеся на сервере, нужно создать заново. API библиотеки защищён авторизацией и проверкой владельца.
