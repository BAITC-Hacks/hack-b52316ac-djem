# Передача проекта другой ИИ: «Аким на 5 часов»

## Коротко о проекте

«Аким на 5 часов» — учебный веб-симулятор управления инвестициями города Астаны для хакатонного спец-трека. Владелец кейса — Astana Innovations. Игрок получает тот же виртуальный бюджет, что и другие игроки, выбирает пять городских мер и видит прогноз последствий для качества жизни по районам.

Стартовый бюджет учебного набора — **10 000 000 000 ₸**. Данные, цены и эффекты — условная модель для демонстрации, а не оценка реальной эффективности государственных расходов и не рекомендация по реальному бюджету.

## Что сделано в этой версии

1. **Брифинг и выбор миссии перед симуляцией.** Игрок начинает с одного из трёх сценариев:
   - «Поднять качество жизни»: общий Score должен вырасти минимум на 2 балла, число критических показателей не должно увеличиться.
   - «Сбалансировать районы»: показатель самого слабого района должен вырасти минимум на 2 балла, городской Score не должен снизиться.
   - «Подготовиться к паводку»: активируется событие «Весенний паводок» с резервом бюджета; пять решений должны добавить минимум 1 балл к прогнозу в тех же условиях без решений.

2. **Итоговый экран игровой сессии.** После расчёта пяти решений игрок видит статус своей миссии, Astana Quality of Life Score из 100, изменение относительно условий той же миссии без решений, потраченный и оставшийся бюджет, количество критических показателей, результат слабейшего района, кольцевую диаграмму расходов по направлениям, меру с наибольшим вкладом и оставшийся риск/компромисс. На этом экране можно открыть презентацию из пяти слайдов или начать новую миссию.

3. **AI-разбор без выдумывания чисел.** Численный Score и прогноз считает серверная модель Python. Если серверный OpenAI API настроен и запрос авторизован, экран использует текст ответа AI. Иначе показывает короткий детерминированный разбор и явно подписывает, что внешний AI не подключён. Ключ в браузер не передаётся.

Изменённые файлы интерфейса: `static/index.html`, `static/app.js`, `static/style.css`. Добавлена эта передача контекста и сценарий презентации в `docs/SHOWCASE_PITCH.md`. Инструкции для сервера находятся в `DEPLOY_BREV.md`.

## Последняя UX-итерация

Интерфейс стал короче по умолчанию: описания и эффекты мер раскрываются по запросу, стресс-событие и разбор сценария свёрнуты, дополнительные действия собраны в отдельном блоке. После расчёта остаётся итог игровой сессии; полный план и карту можно раскрыть отдельной кнопкой. Убрано обещание обязательного AI-анализа из главной кнопки, потому что без серверного ключа работает локальное объяснение модели.

Исправлены зависание старой сводки при изменении плана, рассинхронизация выбранного района карточки меры после перерисовки, восстановление прежнего плана при ошибке смены события, устаревшая подпись кнопки расчёта и вечное отображение старых уведомлений. Текущая версия меняет только static-файлы интерфейса и документацию, поэтому API, зависимости и база данных остаются совместимыми. Пошаговый безопасный переход с предыдущей версии описан в `docs/UPDATE_GUIDE.md`.
## Как устроена игровая логика

- Сценарий и значения по умолчанию находятся в `seed/dataset.json`; сервер создаёт/обновляет рабочую SQLite-базу в `data/` при первом старте.
- Условия и ограничения набора данных проверяются на сервере. Клиентский интерфейс помогает выбрать решения и сразу показывает прогноз; окончательный расчёт выполняется backend.
- Каталог содержит заранее заданные меры и стоимость. В текущем MVP игрок выбирает ровно пять различных мер из каталога, для локальных мер выбирает район. Есть лимит не более двух мер одного направления, ограничения бюджета и конфликты совместимости.
- Это пока не произвольная ползунковая разбивка бюджета: игрок не вводит любую сумму для каждой категории. Стоимость зависит от выбранных мер, а остаток бюджета рассчитывается автоматически.
- Симулятор также поддерживает городские события, сохранение/сравнение сценариев, прогноз, рекомендации/оптимизацию и презентацию. Сравнивайте сценарии с одинаковой версией данных и одинаковым событием.

## Основные части репозитория

- `app/model.py` — расчёт прогноза и Score.
- `app/optimizer.py` — поиск допустимых планов.
- `app/db.py` — SQLite, версии набора данных и сохранённые сценарии.
- `app/agent.py` — серверная интеграция OpenAI и ограниченные инструменты агента.
- `app/main.py` — FastAPI API и отдача веб-интерфейса.
- `app/events.py` — стресс-сценарии.
- `app/presentation.py` — формирование пятислайдовой презентации.
- `static/` — веб-интерфейс и локальные файлы Leaflet.
- `seed/dataset.json` — учебный исходный набор.
- `Dockerfile`, `compose.yaml`, `deploy/` — вариант контейнерного развёртывания с Nginx.
- `DEPLOY_BREV.md` — подробная инструкция для NVIDIA Brev/Jupyter и других вариантов запуска.
- `ACCEPTANCE.md` — критерии и границы кейса.

## Развёртывание на сервере

В поставку входит исходный код без Git-истории, локальной базы, `.env` и ключей. На сервере Linux с Python 3.11+ можно начать по `DEPLOY_BREV.md`. Для варианта Docker Compose нужны установленные Docker Engine и Compose; после локальной настройки `.env` запуск выполняется из корня проекта командой `docker compose up -d --build`. Compose публикует сайт на порту **8080** и хранит SQLite в отдельном Docker volume `city-data`.

Минимальная последовательность для Python-запуска:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python init_env.py
```

Затем отредактировать `.env`: указать публичный hostname в `ALLOWED_HOSTS`. Для AI-разбора дополнительно добавить `OPENAI_API_KEY`; без ключа основная симуляция продолжает работать, но сетевой AI-анализ недоступен. `init_env.py` генерирует разные случайные `ADMIN_API_TOKEN` и `AGENT_API_TOKEN`, если `.env` ещё не существует. Сохранить `.env` только на сервере; не отправлять его в архив, GitHub, чат или браузер.

После запуска проверить `/health`, затем открыть сайт по выданному сервером адресу. Публичный адрес, TLS-сертификат, правила firewall/прокси и постоянное хранилище зависят от конкретного хостинга и должны быть настроены на нём. Само создание архива или ветки GitHub сайт в интернет не публикует.

## Что важно сказать в презентации

Это не обещание, что модель предсказывает реальную жизнь города. Это прозрачная игровая модель, которая позволяет сравнить компромиссы при равных стартовых условиях: цена решения, эффект по районам, слабое место и запас устойчивости. Числа принадлежат учебному датасету; AI объясняет численный результат, но не подменяет модель расчётов. Короткая речь и порядок демонстрации находятся в `docs/SHOWCASE_PITCH.md`.

Не переписывай проект и не меняй `main` без отдельного прямого запроса. Не заявляй, что сайт уже развёрнут публично: для этого требуется реальный доступ к серверу и проверка выданного URL. Не придумывай реальные городские данные, гарантированный социальный эффект или успешный AI-анализ без серверного `OPENAI_API_KEY`. Сначала добейся запуска текущей версии и проверь основные пользовательские шаги; затем перечисли фактически проверенные результаты и оставшиеся ограничения.
