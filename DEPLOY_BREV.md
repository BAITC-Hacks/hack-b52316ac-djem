# Развёртывание на NVIDIA Brev

Сайт проекта: [https://akim-o237lkzkv.gobrev.dev/](https://akim-o237lkzkv.gobrev.dev/).

Ваш Jupyter остаётся на **8888**. Новый сайт: **8080**, Python за Nginx: **8000**. Адрес Jupyter не является SSH-адресом и не становится адресом сайта автоматически.

## 1. Перенести файлы с Windows

Самый быстрый способ — архив `akim-python.zip`, лежащий рядом с папкой проекта. Он не содержит `.env`, ключей и рабочей базы.

1. Откройте ваш Jupyter: https://jupyter-o237lkzkv.gobrev.dev
2. В файловом браузере Jupyter нажмите Upload и загрузите `akim-python.zip`.
3. Откройте Launcher → Terminal. Перейдите в папку, куда загрузили архив (посмотрите `pwd` и `ls`). Выполните:

```bash
python3 -m zipfile -e akim-python.zip akim-python
cd akim-python
pwd
python3 --version
```

Нужен Python 3.11 или новее. Архив распаковывается без дополнительного вложенного каталога проекта.

Альтернатива через Brev CLI в WSL на Windows (замените INSTANCE_NAME именем существующего сервера из `brev ls`):

```bash
brev refresh
brev ls
brev copy /mnt/c/Users/kaira/Documents/Codex/2026-09-23/new-chat/outputs/akim-python.zip INSTANCE_NAME:/home/ubuntu/akim-python.zip
brev shell INSTANCE_NAME
```

Путь `/home/ubuntu` — пример: используйте реальный домашний каталог своего пользователя. CLI копирует в окружение экземпляра; доступ к хосту и контейнеру может отличаться. [Документация переноса файлов](https://docs.nvidia.com/brev/guides/development-tools/file-transfer-scp).

Можно клонировать приватный GitHub-репозиторий, если на сервере уже настроена авторизация GitHub:

```bash
git clone git@github.com:BAITC-Hacks/hack-b52316ac-djem.git akim-python
cd akim-python
```

Если SSH-доступ к GitHub не настроен, используйте загрузку архива. Не вставляйте GitHub-токен в URL команды.

## 2. Настроить окружение

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python init_env.py
nano .env
```

`init_env.py` создаёт два случайных независимых токена доступа. Существующий `.env` не перезаписывает. В редакторе заполните:

```dotenv
OPENAI_API_KEY=ваш_API_ключ_OpenAI
OPENAI_MODEL=gpt-4.1-mini
OPENAI_AGENT_MODEL=gpt-4.1-mini
HOST=127.0.0.1
PORT=8000
ALLOWED_HOSTS=localhost,127.0.0.1,testserver,*.gobrev.dev
TENGE_PER_UNIT=100000000
```

`ADMIN_API_TOKEN` и `AGENT_API_TOKEN` уже сгенерированы — оставьте их значения. Для входа на сайт используйте логин и пароль аккаунта. Редактор доступен администратору; `ADMIN_API_TOKEN` используется для внешних API-интеграций. Ключ OpenAI вводится только в серверный `.env`, не в форму входа. ChatGPT Plus и API — разные доступы. Без API-ключа работают расчёт, карта, сравнение и ручной редактор; нейросетевой анализ честно сообщает об отсутствии подключения.

После получения адреса сайта лучше заменить `*.gobrev.dev` на точное имя хоста без `https://` и без `/`. Если Brev выдаст другой домен, укажите его. `Invalid host header` означает, что домен отсутствует в `ALLOWED_HOSTS`; после изменения перезапустите Python.

## 3A. Быстрый запуск из Jupyter Terminal

Если Docker и Nginx недоступны в контейнере Jupyter, сайт можно сразу поднять на 8080:

```bash
mkdir -p logs
nohup env HOST=0.0.0.0 PORT=8080 .venv/bin/python run.py > logs/app.log 2>&1 &
echo $! > logs/app.pid
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ: `{"status":"ok"}`. Это прямой запуск Python, подходящий для демо через HTTPS-туннель Brev. Процесс переживает закрытие терминала, но не перезагрузку сервера. Повторно команду запуска не выполняйте, пока предыдущий процесс работает. Остановка только своего сайта: `kill "$(cat logs/app.pid)"`. Jupyter не останавливайте.

## 3B. Запуск с Nginx без Docker

Используйте этот вариант вместо 3A. Требуется установленная команда `nginx`. На Ubuntu-хосте с sudo её можно установить: `sudo apt-get update` и `sudo apt-get install -y nginx`. В контейнере Jupyter sudo может отсутствовать; тогда используйте 3A либо подключитесь к хосту.

```bash
mkdir -p logs
nohup env HOST=127.0.0.1 PORT=8000 .venv/bin/python run.py > logs/app.log 2>&1 &
echo $! > logs/app.pid
nginx -p "$PWD/" -c deploy/nginx.conf -t
nginx -p "$PWD/" -c deploy/nginx.conf
curl http://127.0.0.1:8080/health
```

Полный конфиг: `deploy/nginx.conf`. Он слушает непривилегированный порт 8080, проксирует на 127.0.0.1:8000 и хранит PID/логи внутри проекта. Изменённый конфиг применить: `nginx -p "$PWD/" -c deploy/nginx.conf -s reload`. Остановить этот экземпляр: та же команда с `-s quit`.

## 3C. Docker Compose — вариант с автоперезапуском

Используйте вместо 3A/3B, когда `docker info` и `docker compose version` успешно выполняются. Jupyter может работать внутри контейнера без доступа к Docker хоста.

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=80
curl http://127.0.0.1:8080/health
```

Nginx слушает 8080, Python доступен только внутри Docker-сети. База хранится в постоянном томе `city-data`. Конфиг: `deploy/nginx-docker.conf`. GPU для вызова OpenAI API не требуется. Не запускайте одновременно несколько вариантов на 8080.

## 4. Сделать сайт доступным по ссылке

В консоли Brev откройте существующий экземпляр → **Access → Using Tunnels → Add Port**, добавьте **8080** и откройте выданную ссылку. Не меняйте туннель Jupyter на 8888. [Официальная инструкция](https://docs.nvidia.com/brev/cli/connectivity).

Сайт будет доступен через интернет при работающем сервере и туннеле. Но secure link может требовать входа NVIDIA/Brev: проверьте ссылку в приватном окне браузера, прежде чем отправлять жюри. Наличие URL не гарантирует анонимный доступ. Если консоль предлагает настройки доступа — выберите нужный режим; иначе предоставьте проверяющим предусмотренный Brev доступ или используйте свой публичный домен/порт. [Brev Console Reference](https://docs.nvidia.com/brev/guides/console-reference).

`brev port-forward INSTANCE_NAME --port 8080:8080` открывает локальный SSH-туннель на вашем компьютере, а не общедоступную ссылку.

## 5. Нужен ли сертификат

Для выданной Brev ссылки с `https://` TLS обслуживается на стороне туннеля. Отдельный сертификат внутри Nginx на 8080 не нужен: он принимает HTTP за HTTPS-туннелем. Проверьте действительность HTTPS в браузере.

Для собственного домена при прямом доступе к серверу нужен TLS-сертификат. Не пытайтесь выпускать сертификат на чужой домен `gobrev.dev`. Необходимы собственный домен, DNS на доступный публичный IP сервера и разрешённые входящие 80/443. Не все конфигурации Brev дают прямой доступ к этим портам.

На Ubuntu-хосте при выполненных условиях установите Certbot согласно [официальной инструкции для Nginx](https://certbot.eff.org/instructions?ws=nginx&os=pip). Сначала настройте обычный сервер Nginx на 80 с вашим `server_name` и `proxy_pass http://127.0.0.1:8080;`, проверьте доступность домена, затем:

```bash
sudo certbot --nginx -d YOUR_DOMAIN
sudo certbot renew --dry-run
```

Certbot установит сертификат и предложит HTTPS-перенаправление. Этот вариант относится к системному Nginx на хосте; не запускайте его в приложении/контейнере Jupyter без соответствующего окружения.

## 6. Агент, данные и обновления

На сайте: «Войти» → аккаунт администратора → «Данные и агент». Пример поручения: «Прочитай текущие данные. Измени T1 района Нура на 60, затем объясни изменение». Агент вызывает проверяемые функции Python, а база сохраняет версию и аудит. Внешний агент может использовать `/docs`, `/openapi.json`, `/api/agent/tools` и `/api/agent/execute` с заголовком `Authorization: Bearer <AGENT_API_TOKEN>`. За secure tunnel внешнему клиенту также может потребоваться доступ Brev.

Агент редактирует весь рабочий датасет, стоимость и эффекты мер, показатели, бюджет, сценарии и видимые тексты сайта. Не получает произвольный SQL, исполнение команд сервера или доступ к `.env`. Ограничения кейса и история изменений сохраняются. Для восстановления используйте выбор версии в редакторе.

Новая версия кода при развёртывании из GitHub:

```bash
git pull --ff-only
docker compose up -d --build
```

Для нативного запуска после обновления зависимостей перезапустите только Python-процесс сайта. Не удаляйте `data/`, `.env` или Docker-том базы. Изменение `TENGE_PER_UNIT` действует при первом создании базы; существующие цены меняются через версионируемый редактор.

Резервная копия при нативном запуске: `.venv/bin/python backup_db.py`. Для Docker: `docker compose exec app python backup_db.py`, затем скопируйте полученный файл из `/app/backups/` на хост через `docker compose cp app:/app/backups/ИМЯ_ФАЙЛА ./`. В архиве бэкапа может быть пользовательская информация — не публикуйте его в GitHub.

## 7. Проверка перед показом

- `/health` отвечает `ok`; в браузере исходный Score 52,56, бюджет 10 млрд ₸.
- Пять мер меняют диаграмму и Score, недоступные по бюджету кнопки блокируются.
- «Найти лучший план» для исходной версии даёт 57,236735 при расходе 9,8 млрд ₸.
- Сценарий сохраняется и доступен после перезапуска.
- С настроенным API-ключом выполните один анализ и одну тестовую правку агентом, затем восстановите исходную версию.
- Откройте публичную ссылку с другого устройства/в приватном окне. Доступность Jupyter сама по себе не проверяет доступность сайта.

Проект проверен локально на Windows. OpenAI с локальным ключом проверен. Реальный сервер Brev и Linux Nginx/Docker требуют проверки после развёртывания. Для проверки установленного сайта выполните `python verify_install.py --url http://127.0.0.1:8080 --live-ai`. Эта команда делает один платный AI-анализ и не меняет рабочие данные.


## Обновление с аккаунтами

Загрузите akim-accounts-update.zip в /home/ubuntu через Jupyter. В терминале:

```bash
cd /home/ubuntu/akim-python
.venv/bin/python backup_db.py
cd /home/ubuntu
python3 -m zipfile -e akim-accounts-update.zip akim-python
cd akim-python
bash deploy/restart_brev.sh
```

Обновите браузер Ctrl+F5. Вход: admin / admin, если администратор ещё не существовал. Создайте сотрудников в «Данные и агент», смените начальный пароль в «Главная → Настройки аккаунта». ZIP не содержит .env, БД и пользовательских данных. Миграция происходит при запуске; зависимости не изменились. Если logs/app.pid отсутствует или устарел и порт занят, скрипт не завершает неизвестный процесс: проверьте `ss -ltnp 'sport = :8080'` и остановите прежний способ запуска приложения.

## Актуальное объединённое обновление

Используйте `akim-merged-update.zip`. Порядок установки, резервная копия и откат: [docs/UPDATE_GUIDE.md](docs/UPDATE_GUIDE.md). Добавлены миссии и итоговая сводка; аккаунты, библиотека результатов и текущие данные сохраняются. Для этой поставки нужны новые модули `static/missions.js` и `static/api-response.js`, поэтому старой инструкции о трёх статических файлах недостаточно.
